# 旅遇：从 MVP 到生产发布

当前版本用于产品演示与用户测试。正式开放注册前，需要完成以下工作。

## P0：上线阻断项

- 升级到仍受安全支持的 Next.js 版本并重新执行依赖审计。Next.js 14.2.35 已是 14 系列最后补丁，但当前审计仍报告上游安全通告。
- 接入真实 Supabase 项目，执行迁移并使用两类账号验证全部 RLS 策略。
- 将搭子双方确认与创建小组合并为服务端数据库事务，客户端不能直接添加成员。
- 为 Claude 接口加入登录校验、速率限制、用量预算、超时、重试和审计日志。
- 实名认证、SOS、紧急联系人保持关闭或明确标记为演示，直到真实供应商、安全审计和应急流程完成。
- 完成隐私政策、用户协议、数据删除与账号注销流程；根据目标市场完成合规评审。

## P1：内测前应补

- 单元测试：JSON 容错解析、货币最小单位、分摊余数、可见性规则。
- 集成测试：登录、生成行程、匹配确认、建组、消息、发布攻略。
- E2E：覆盖主闭环与未登录公开攻略。
- 社区治理：举报、拉黑、内容审核、风控和申诉。
- 匹配安全：年龄限制、敏感信息提示、异常行为检测、首次见面安全指南。
- 可观测性：错误追踪、结构化日志、关键漏斗事件和 AI 成本监控。
- 图片上传：格式/大小限制、病毒扫描、EXIF 与精确位置清除。
- 消息能力：未读数、重连、离线状态、消息删除规则。

## P2：公开发布前优化

- 接入高德地图并补齐 POI 版权归属、配额、缓存与失败降级策略。
- 使用真实汇率数据，并记录汇率来源与时间；AA 模块仍应避免触碰资金托管。
- SEO、Open Graph 分享卡、站点地图和公开攻略结构化数据。
- 性能预算、图片 CDN、无障碍审计和低端设备测试。
- 灰度发布、数据库备份恢复演练和事故响应手册。

## 建议发布阶段

1. 私有 GitHub 仓库：团队代码评审与 CI。
2. Preview 环境：仅邀请的产品和设计评审。
3. 封闭内测：Mock 安全能力继续保持显著标识。
4. 完成 P0 后再开放真实用户注册。
